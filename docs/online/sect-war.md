# 門派會武（EA0.100.0）

入口：江湖 → 江湖風雲 → 門派會武。獨立全屏，保留返回、暫停、跳過、重播及名冊；戰報可離線參戰，毋須房間或二十人同時在線。衣著與頭部讀取玩家既有造型，正式開戰後鎖進該份戰報。

## 正式資料流程

1. 沿既有 Supabase 身份連線；報名／選拔／開戰前先保存玩家對戰配搭。
2. `jianghu-sect` 驗證 JWT 身份、來源、輸入及權限，從既有雲端存檔讀取人物；前端不能提交能力、代表隊、勝方或獎勵。
3. 獨立門內排名選十名代表，本屆席位鎖定。選拔沿用現有一對一核心；不回寫健康、內力、傷勢、死亡或單機門派地位。
4. 同週同對手只保存一場。服務端用對戰配搭建立二十人快照及完整時間軸，CAS 交易一次保存世界、戰報、指令收據；報名與戰爭資料不混入舊共用江湖。
5. 正式播放器只解碼已保存幀，不重新執行目標選擇、RNG 或傷害運算。坐標量化到 1/64 世界單位只供畫面；氣血／內力保留 Float64，事件保持原值。JSONB 重新排列物件鍵不影響校驗。
6. 跳過／重播／關閉／切頁只改播放游標。暫停、背景及模態名冊停畫，不補播積壓時間；減少動態直接讀結果。

表：`jianghu_sect_world`、`jianghu_sect_reports`、`jianghu_sect_receipts`。全部開 RLS、撤銷瀏覽器角色讀寫；只有已驗身份 Edge 經 service role 呼叫 SECURITY INVOKER CAS RPC。`unique(term,pair)` 防止同週對手重複戰報；操作編號收據處理遺失回覆／連點重試。沒有修改舊 pair／world 的資料表或重新部署其函數。

對外戰報只包含戰鬥需要的白名單人物欄位與衍生戰鬥狀態；不含玩家玉石、家族故事、人生旗標或年譜。沿用原有雲端存檔的信任邊界：成長資料仍不是完全伺服器權威，不能宣稱已完成反作弊或可接入現金交易。

## 封測規則（不是永久經濟定案）

集中在 `data/redesign/sectWarTestParams.ts`：香港週一04:00換屆；掌門一席、長老兩席、執事三席、代表四席；首屆滿十人先成隊；門內選拔冷卻一分鐘；同週同對手一場；最多二百個報名身份。平時比武可改下屆排名，本屆職位不變。換屆移除已離派、死亡或不存在的人物；戰前發現代表不能出戰會拒絕，不代填示範人物。

戰鬥範圍與速度沿多人測試參數；普通演武／一對一的原有規則不變。**本版沒有新增會武資源獎勵**，以免把尚未確認的經濟寫入核心。幫會十城、城池資源分配、正式賽季與候補政策仍待後續確認。

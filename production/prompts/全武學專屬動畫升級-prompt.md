## 一、目標與品質參照

先讀 repository 最新 `AGENTS.md`、`production/redesign-scope.md` 及實際程式，確認最新版本。不要回退或覆蓋既有功能。

以遊戲現有「寶箱開箱／結果揭曉」的完成度作為品質參照：主體清晰、蓄力有層次、爆發有重點、材質精緻、動作有重量、音畫同步、殘留效果自然收束。參考以下實際檔案及開發版演出：

- `design/ux/highlight-fx.md`
- `src/fx/highlight/director.ts`
- `src/fx/highlight/scene/models.ts`
- `src/fx/highlight/scene/renderer.ts`
- `src/fx/highlight/highlight.module.css`
- 開發版 `?fx=highlight&mode=chest`，檢視不同品階的實際動態。

參考的是演出品質與編排方法，不是將寶箱模型、開箱流程、滿屏閃光或數秒等待搬到每一次攻擊。戰鬥必須仍然流暢，正常掛機不能每招都被過場打斷。

沿用現有淺色水墨武俠美術：宣紙、墨韻、低飽和礦物色、少量朱砂／泥金。可以華麗，但不得改成紫色霓虹、科幻光炮或過曝光污染。粒子、光暈及震屏是輔助，人物的真實動作才是主體。

## 二、第一優先：名稱、肢體與武器必須相符

**拳必須用拳，掌必須出掌，腿必須踢腿；不能所有招式都讓同一個持劍角色揮一下，再換顏色與粒子。**

逐門讀取武學名稱、招式名稱、描述、武學類型、`weaponKind` 及現有機制，建立明確的 `artId → 動作類型／持武／專屬編排` 映射，不要只靠名稱包含某個字來猜，更不要把六個流派當成六種動畫。

| 武學表現 | 必須看見的動作 | 本招主角動作與特效禁止出現 |
|---|---|---|
| 拳法 | 握拳、收拳蓄勢、蹬地轉胯、拳鋒接觸與回收 | 手持／揮動刀劍、劍氣、以劍尖作命中錨點 |
| 掌法 | 開掌、送掌、推掌／劈掌，掌心勁力方向明確 | 將掌套用成握劍劈砍，或只畫巨大掌印而人物不出掌 |
| 腿法 | 支撐腳、提膝、踢擊／迴旋、重心轉移與落地 | 主角用刀劍完成攻擊、腳沒有動但只播放旋風 |
| 劍法 | 正確握劍，刺、挑、削、點等符合該門意境 | 大刀式重劈替代所有劍術，或兵器離手漂浮 |
| 刀法 | 刀刃、握柄、斬劈軌跡與刀勢重量 | 直接換成細劍、憑空出現無關兵器 |
| 槍／棍／鞭／暗器 | 各自合理握法、長短、慣性、伸展或投射軌跡 | 通用揮劍姿勢，暗器尚未投出就先命中 |
| 內功 | 對應原效果的運氣、調息、護體或內勁視覺 | 沒有機制依據的攻擊、額外傷害、回血或護盾假象 |
| 身法／步法 | 步伐、閃身、重心、殘影方向與落腳 | 只平移整張人物，腳底滑行，或無依據的揮劍攻擊 |
| 棋局等特殊武學 | 按名稱與描述設計可辨識的專屬手勢和意象 | 一律套用魔法陣、劍雨或通用爆炸 |

上表限制指本招的主角與生成效果；敵人的兵器仍依其身份正確顯示。

即使玩家裝備欄持劍，施展拳法時亦必須以空手動作出拳；出招期間收起或隱藏主角動作層中的不相符兵器及其殘影，結束後才按正常待機規則恢復。這只是視覺切換，不得偷偷換裝、改裝備屬性或修改兵器相契加成。

如果現有整張剪影／攻擊圖本身已畫有劍，單純關閉外加武器圖層並不足夠：必須補上真正的空手／對應兵器動作素材。禁止用「程式設定已是 fist」代替肉眼驗收。

遇到名稱、描述及資料欄位互相矛盾，列出具體武學及衝突，分清楚修正顯示映射與修改玩法資料。不要擅改武學名稱、`kind`、`weaponKind` 或戰鬥數值以遷就動畫；可先完成其他沒有歧義的項目。

## 三、全部武學覆蓋，每門有自己的身份

從真實武學目錄產生清單，按 canonical ID 處理舊名別稱，報告實際總數、已完成、待完成及有歧義項目。不可只完成八套示例便聲稱全武學已完成。

每門至少交付：

1. 名稱與招式神髓的解讀依據。
2. 空手或兵器類型、握點、拳／掌／腳／刃尖等命中錨點。
3. 待機銜接 → 起手蓄勢 → 出招／移步 → 接觸／命中 → 收招恢復的關鍵姿勢與時間線。
4. 至少兩項人物動作層面的辨識差異，例如發力姿勢、步法路線、攻擊方向、連擊結構、停頓節奏或收招方式；另有一項與名稱對應的招牌視覺設計。
5. 對應真實結果的命中、落空、防禦、暴擊及擊倒表現；沒有該機制便不得憑動畫新增。
6. 資產來源、圖集、腳底／手部錨點、動畫 ID、適用入口與驗收狀態。

可共用基礎骨架、素材管理及受擊系統，但不得以改色、改粒子圖、改 `motion` 字串、微調參數或複製同一條時間線當成每門獨特動畫。同類拳法也要有明確的動作與節奏差異。

### 每門武學的辨識度是硬性驗收條件

**每一門武學都必須擁有自己的動畫身份，包括一般武學、同類武學及同流派武學；不能只有珍本有特色，也不能整個流派共用一套動畫。** 稀有度決定動作與特效的豐富程度，每門武學的神髓則決定具體演出內容；兩者必須同時成立。

逐門建立「武學識別卡」，至少列出：

- **起手輪廓**：站姿、手形、重心及準備動作。
- **主動作特徵**：發力方向、步法路線、攻擊軌跡及身體協調。
- **節奏指紋**：快慢、停頓、爆發位置與收放，全部對應原有戰鬥結果。
- **招牌意象**：名稱與描述所對應的獨有筆觸、形狀、材質或環境回應，不能只換顏色。
- **收勢與餘韻**：完成姿勢、步伐回收、衣擺及效果散去的方式。

共用底層骨架與部分素材可以，但同類武學必須有實際可見的編排差異。例如不同拳法可分別強調連續崩拳推進、沉腰近身短打或迴身反擊；不能所有拳法都做同一個直拳，再分別加水、火、金光。所有設計仍須逐門對照真實名稱與描述，不可為求不同而亂加不相符動作。

驗收時，每門指定一門最容易混淆的同類武學，提交並排錄影，列出至少兩項人物動作差異與一項招牌視覺差異。先隱藏名稱、流派及稀有度標籤，再用統一色調與關閉附加粒子的版本檢視人物動作；看過對照後仍應能分辨兩門編排，恢復特效後則能進一步認出各自神髓。

不能只證明「看得出拳與劍不同」，也要證明「兩門拳法、兩門劍法、兩門內功或身法各有自己的特色」。若辨識必須依賴名稱、配色、稀有度標籤、傷害數字或解說文字，該門辨識度未通過，需重做後才可標記完成。舊名別稱對應同一canonical武學則共用身份，不重複計數。

同一套外功的七卷沿用既有決定：可共享該門的核心動畫身份，按實際戰報及節奏編排，不強制擴成七套互不相干的新動畫。

### 方向示例，必須以真實資料核對

- **長河拳**：空手連續崩拳，以蹬地轉胯逐拳推進；水墨浪勢隨拳鋒推出，主角清晰可見，不得揮劍。
- **裂石殘掌**：沉腰蓄掌、開掌發勁；裂紋由掌勁接觸處延伸，碎石和塵土有重量，不是任意位置爆炸。
- **聽雨劍意**：靜候、聽雨、短促精準刺擊；雨滴與劍尖接觸節點呼應，以靜制動，不套用大刀亂斬。
- **驚雷刀**：提刀蓄勢後重劈，雷紋沿刀路落下；落點、受擊及塵土同拍，不先中雷後揮刀。
- **唐門飛針**：手指與手腕投針，細密暗器沿清晰路徑飛出，抵達目標才出命中；不得借劍氣代替飛針。
- **身法／步法**：以真實移步、閃身及足底錨點建立速度感，不因為名稱有「步」就忽略它在資料中可能是外功；按實際動作語義設計，保留原玩法類型。

## 四、按寶箱完成度編排戰鬥，而非堆砌特效

每套動畫需要清楚的力量傳遞：準備姿勢、重心、身體發力、武器／肢體軌跡、接觸瞬間、敵人回應、餘勢及回收。

- 蓄力粒子必須朝正確的手、腳或兵器匯聚；不能只朝人物中心吸入。
- 命中特效從真實接觸點出現，方向與速度跟隨攻擊。衝擊、飛白、碎屑、衣擺及音效有主次。
- 同步近景受擊、遠景環境、地面塵土及少量殘留痕跡。飛針、碎石、衣擺不能毫無慣性地停止。
- 腳底錨點與地面保持一致；起跳、落地及接觸陰影互相對應，避免浮空走路與瞬間穿地。
- 倒地需有失衡、承重、身體接地及餘勢，不是整張圖旋轉後淡走。
- 正常招式、重擊及終結可分層強度，不得每次普通攻擊都使用最高級全屏震動與閃白。
- 音效對應拳肉、掌風、刀斬、劍鳴、暗器、內息等實際行為；遵守靜音設定，不堆疊到削波。
- 特效不能長時間遮住角色、敵人、雙方血條、武學欄、數字及操作。玩家必須看得清自己出了甚麼招。

## 五、按武學稀有度分配動畫豐富度與華麗程度

**武學稀有度越高，獨立動作、動畫變體、細節層次與招牌特效必須越豐富，整體演出越華麗、越精緻。不能所有稀有度共用同一套動作，只改成金色便當成高品質武學。**

先核對正式武學稀有度的資料來源，提交「武學ID → 正式稀有度 → 動畫規格 → 已有素材／待製作素材」對照表。稀有度與熟練階位、秘笈升星、卷數、心願命中及付費取得方式是不同概念，不得混為一談。尤其不能直接把抽卡揭曉的品階色當作該門武學的永久稀有度。

目前目錄有 `premium` 珍本標記；如實際版本只有一般／珍本兩種分類，先依既有分類做兩檔，預留更多正式稀有度的映射，不得憑空新增六級玩法稀有度。若有額外正式稀有度資料，按其順序逐級提高下列規格；有歧義的映射先列明待確認，不擅改取得方式或武學強弱。

| 動畫規格 | 一般／較低稀有度武學 | 高稀有度／珍本武學 |
|---|---|---|
| 基本完整度 | 每門至少一套完整、獨特且符合名稱的招式動畫 | 同樣完整，另增加更多獨立動作片段及過渡姿勢 |
| 動作變體 | 完整主招，保留真實落空／受擊的正確表現 | 在引擎實際提供的條件下，增加重擊／暴擊、終結或其他合適變體，目標至少三種可辨識編排；若核心不提供相應情境則列明，不虛構觸發 |
| 發力與身法 | 清楚的準備、出招、接觸及收勢 | 更細緻的轉胯、步伐、手法變化、蓄勢轉折及收招餘韻，仍符合該門神髓 |
| 招牌特效 | 一個清晰主題，適量軌跡及命中效果 | 多層但有主次的專屬筆觸、氣勁、材質細節、前後景與環境呼應 |
| 音畫與細節 | 準確同步的基本打擊聲及簡潔餘勢 | 更豐富的蓄勢、接觸、重擊及餘韻聲層，精緻衣擺、殘影與地面回應 |
| 稀有度辨識 | 乾淨俐落、易讀，不靠粗糙素材壓低質素 | 不看名稱與品階標籤，也能感受到更豐富的編排與更高的製作投入 |

「更多動畫」必須體現在真正不同的關鍵姿勢、動作片段、銜接與可辨識變體，不是複製幀、把同一動作播兩遍、把時間拉長或只增加粒子數。若新增多個表現段落，仍是呈現原有戰鬥事件，不得因此多扣一次血或增加一次攻擊。

所有稀有度都有同一套角色結構、持武正確、地面接觸及流暢度底線。低稀有度可以簡潔，但不能變成粗糙佔位圖；高稀有度的拳法再華麗也必須空手出拳，不能因為升級便長出劍氣、刀光或不相干的兵器。

高稀有度也不能每次出招都長時間全屏閃白、震屏或播放過場。為連續掛機提供節奏緊湊的常態版，在既有重擊／終結等合適情境呈現更豐富的高光版；兩者均保留該門的稀有度細節及獨特身份。內功與身法的高稀有度表現增加運氣、步法、殘影與材質細節，不能擅加不存在的護盾、回血或攻擊。

驗收時另外提供相近武學類型的低／高稀有度並排正常速度錄影，標示實際增加了哪些姿勢、變體、專屬素材與環境層次。不能只以文字宣稱高稀有度「更華麗」；映射、動畫資產數及實際成品必須對得上。

## 六、素材與實作方式

優先使用 AI 生成的原創水墨角色動作、透明序列幀／圖集及高質感特效位圖，再以現有引擎做時間線、混合、遮擋、位移與鏡頭整合。

禁止 SVG、火柴人、Canvas path 人偶或粗糙幾何人物冒充商業角色動畫；允許現有 Canvas／WebGL 繪製及合成高品質位圖，既有 Three.js／GSAP 架構可合理沿用。

AI 出圖要求：同角色造型、服裝、比例、持武、攝影角度及輪廓一致；手腳結構正確，關鍵姿勢有連續性；透明背景乾淨，無文字、水印、棋盤格假透明及額外肢體。空手素材明確排除刀、劍、劍鞘及武器殘影。逐格檢查握點、腳底、遮擋及拼格，禁止盲目平均裁切。

幀數、解析度與檔案大小按實際播放尺寸、動作及手機預算制定，不能靠寫「60fps」或堆很多相似圖片宣稱品質。保留生成原圖、生成提示、模型／來源、處理腳本、圖集映射與授權紀錄。WebP／PNG 等位圖格式依透明度與播放需要選擇；製作工具只裁切、校正、壓縮及合成，不能用粗繪圖取代應有素材。

若生成工具或額度不可用，清楚標記素材阻塞及未完成範圍，繼續可獨立完成的審核、映射與原型；不可把佔位圖當完成品，也不要叫玩家在對話貼 API key。

## 七、戰鬥結果與現有功能不得被演出改寫

保留最多五門外功、內功一門、身法一門、跨派配搭及現有裝備流程。

動畫只消費真實戰鬥狀態／戰報：總傷害、命中、勝負、回血、內力、冷卻、敵人行動、獎勵及核心 RNG 均不得因特效改變。不能為了動作好看，額外命中、憑空暈眩／回血、提早判死或給不存在的無敵時間。

多段視覺命中須明確區分「同一筆結果的表現分段」與「核心原有多次命中」；分配含尾數補齊，總量守恆，每個核心事件只能結算一次。不能在每一幀／每個粒子／每次回放重複扣血。落空不得顯示命中特效、扣血、受傷或擊倒。死亡、中斷、切換敵人、跳過及重播要依既有身份與事件處理。多段是否可轉移目標依現行核心規則；事件需綁定正確攻擊／目標身份，不得由粒子或延遲回呼另行決定。

視覺停格、慢鏡及長動畫不可以偷偷增加輸出時間或延遲敵方攻擊。若現有演出與核心時計耦合，先說明影響並做隔離驗證，不能直接更改數值補償。純視覺 RNG 獨立於核心 seeded RNG。

## 八、效能與後備

按當前角色、敵人及已裝備武學分批預載，圖集／紋理共用及快取，不可首次開頁下載全部武學全部動作。限制同時存在的粒子、殘影與紋理；釋放事件、音效節點、計時器、Canvas／WebGL資源。

保留加速、跳過、靜音、暫停／恢復、切頁、敵人倒地及連續輪替的穩定性。效能降級應先減次要粒子／解析度，保留正確的武器、關鍵姿勢、接觸點與結果。資產未載入、WebGL不可用或減少動態時，也不能退回錯誤的通用揮劍。

減少動態模式不震屏、不強閃、不推拉鏡頭，保留易讀的低動態招式識別及正確結果。手機以穩定60fps為目標，量測實際幀時間、峰值記憶體及載入成本；不達標時列出裝置、瓶頸與降級方式，不能以桌面模擬當真機通過。

## 九、執行次序與驗收

1. **審核**：交出全武學對照清單、稀有度映射與動畫預算、實際入口、目前共用動作／持武問題及缺素材項目，說明完整製作計畫。
2. **代表性原型**：先完成拳、掌、腿、劍、刀、長兵器、暗器，以及內功／身法的代表樣本，並包含低／高稀有度對照。交真正遊戲畫面的正常速度與慢速錄影，讓玩家確認質素和方向，再擴展全目錄。
3. **全量製作**：每門有可核對的動作、素材及編排；保留前面已確認的共用規格。未完成必須明列，不可以通用揮擊後備冒充100%覆蓋。
4. **完成驗收**：全部真實入口與正反方向、不同敵人、連續輪替、落空／暴擊／死亡／中斷、加速／跳過、資產失敗及減少動態均驗證。全武學逐門有實際動態證據，不只用隨機抽幾門代表全部。

交付清單：

- canonical武學清單及每門動畫設計／覆蓋狀態；逐門五項武學識別卡、最易混淆武學對照及辨識度驗收結果；正式稀有度映射、動作／變體／素材投入對照，舊名對照與歧義記錄。
- 正式接入程式、原始素材、生成提示、圖集／錨點映射及可重跑處理腳本。
- 開發版驗收頁：可選武學、播放速度、結果情境及對照動作；必須使用產品同一套呈現器，不計為正式接入的替代品。
- 固定seed42、390×844、DPR2的改前／改後截圖，逐門關鍵幀接觸表及真實GIF／MP4。錄影必須清楚看到人物動作與接觸點，不能只有漂亮特效靜圖。
- 特別提交「裝備劍但施展拳法／掌法／腿法」的全段錄影：主角及本招不得出現揮劍、錯誤武器、劍氣或武器殘影。再錄製切回劍法，確認正確恢復。
- 以單元／整合測試檢查全目錄映射、別稱、動畫完成回收、武器限制、命中一次性及傷害守恆、視覺RNG隔離、對戰結果一致。只測 `motion` 字串不同或映射表存在，不足以驗收動作獨特性。
- 跑 repo 要求的完整測試、build、narrate檢查，提供效能記錄、真機／模擬範圍及已知限制。

最終判定：遮住武學名稱和華麗粒子後，仍然看得出主角在出拳、出掌、踢腿還是使劍；同類武學在隱藏名稱與統一配色後仍有各自可辨的動作神髓，高稀有度武學在動作豐富度、變體及專屬視效上有實際可見的提升。任一拳法仍在揮劍，或只有換色／共用揮擊，就不算完成。

# 第60f項 · 全武學獨立動畫

玩家已回覆「保留」：繼續使用所選面孔、衣著及配色。本輪103門、19類各自有明確動作編排；正式交手以同一套骨架來源的整體位圖播放，保留既有打擊編排及結算時計。發布目標EA0.102.0，PR #159。需求確認不等於玩家已接受這批畫面；未作真iPhone或新TestFlight驗收。

## 製作與真接入

- 96個明確姿勢語彙、103段不同骨架軌跡，不以ID雜湊、改速、換色或粒子當獨立動作。
- 每衣131段（103武學＋28生命週期），三衣393段、13,224幀；八頭×三衣共24張連續上身圖集，每張13個受限轉頭預設；四色按原外觀ID套用。
- 拳／掌／指／捏／握／拉弦／簫／棋子使用各自手形。鉤、戟、簫、機關、針、鏢不是劍槍棍代替。弓弦讀同幀副手，柔鞭固定鏈長連接，機關跟腕點，空手時適合背負的真裝備兵器放到背部。
- 頭、頸、上胸是同一連續材質；正常播放先預合成整體，不讓頭與身分開更新。身高及原點固定，倒地按真alpha落地，不按每張圖的包圍盒重新放大。
- 單人與非同步一對一使用同一呈現器；對手按真戰報取當次武學。沒有接入暫停的幫會／門派戰，也不把未使用的舊Three預覽稱為全量完成。
- 同一門七卷共用該門編排、讀真卷序，沒有假稱721套動作。內功／身法只跟真支援事件，沒有額外傷害或派獎。

來源、生成提示、拒絕素材、裁切／alpha處理、綁定與可重做腳本見`design/art/independent-animation/README.md`；本輪來源與完整表見`artifacts.json`及`motion-coverage.md`。

## 實際檢查

`app-binding.json`：103門×三衣共309例，產品SparStage取正確武學與family，真呈現器逐幀繪製10,467個武學幀；另驗96個頭／衣／色組合的出招、受擊與倒地。包括鏡像、減少動態、人物可見性；pageerror0、localStorage不變。生命週期幀另列在artifact總數，不混稱武學數。

`battle-browser-report.json`：Chromium及Linux WebKit，演武核心、江湖交手與首領三入口，共6例；兩個所選造型、加速、連按跳過、重播、背景暫停與恢復通過，沒有存檔寫入或重複結算。

`device-browser.json`：兩引擎320×568、430×932、390×844減少動態，以及強制全部新動畫素材失效，共8例。沒有橫向溢出或pageerror，失圖保留所選面孔／衣著／色並由舊完整姿勢承接，跳過仍可用。這是Linux瀏覽器，不是真iPhone。`failure-browser.json`另有兩引擎真交手的全新素材失效、連按跳過及重播驗證，存檔不變。

新增測試使用固定版本的真Spine Runtime驗證三衣所有輸出採樣：骨長、接點、肘／膝限角、有限數值、關節跳變及雙手同桿握點。另測103段軌跡不同、舊8套時計與接觸點不變、同幀副手地掌錨點、固定比例及整體一次繪製；快取超限須真正釋放舊Canvas，失圖冷卻不能每幀重試。原66外功的結算／敵方行動隔離回歸保留。

## 已修正及效能界線

製作時發現重刀副手投影可翻肘，已改成兩個真握點的解析閉合；掌心握點與兵器軸分開，不用拉長肢體掩蓋。手腕由有界關鍵姿勢連續過渡，刪除180度突跳；聽雨劍的短回劍改緊湊收腕。袖口蓋腕材，透明像素清RGB，避免紅／黃透明邊污染。

身體快取最多32段及24M像素，上身最多4個外觀，完整幀最多96張；淘汰時清空Canvas釋放底圖。正式版只預載當場真武學與需要的生命週期，不預載103門；人物頁靜態立繪沿用原路徑。

`performance.json`保留同一凍結舞台的首次／暖快取Canvas提交時間、舊後備參照及10,000次繪製壓力檢查。這些是桌面CPU提交時間與瀏覽器JS記憶體估算，不是GPU完成時間、顯示幀率或iPhone記憶體。舊後備有長停頓離群值，因此不宣稱本輪幀率提升幾倍。真iPhone、持續遊玩熱穩定、原生編輯器回合及新TestFlight仍待實機驗收。

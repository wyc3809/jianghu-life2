# 玩家文字規範

遊戲顯示文字統一使用繁體中文書面語。介面說明以清楚、簡潔為先；事件對白保留人物語氣，仍使用書面語。武學、流派、人物名稱及既有專有術語沿用原名。

- 操作按鈕直接說明行動，例如「返回」、「關閉」、「確認」、「查看變化」。
- 規則先寫適用條件，再寫結果；成本、期限、保底與死亡風險不可省略。
- 敘事交代人物做了甚麼、對方如何反應，以及事情有何結果。不重複事件標題與選項，不以空泛感想收尾。
- 比喻用於交代可見的招式或場景，不用於代替實際結果。不以篇幅判斷品質。
- 不把製作說明寫進遊戲，例如「不是下拉選單」或「失敗寫得很具體」。
- 不補寫未實際取得的武學、玉石、書頁或數值。劇情中的證物不等於新增行囊道具；實際獎勵以結算欄為準。
- 錯誤提示交代問題及下一步。服務回傳舊口語時，由介面轉成書面語；未知英文錯誤使用中文後備提示。

| 原文 | 修訂 |
| --- | --- |
| 唔保證有武功 | 不保證獲得武功 |
| 修為保留，一點唔扣 | 修為全數保留 |
| 返去抽秘笈 | 返回抽取 |
| 根骨福緣……改寫一寸 | 初始屬性已根據童年選擇調整 |
| 像把故事撕掉半頁 | 沒有介入，隨後離開 |

`npm run audit:copy`檢查程式與內容中的中文字串及JSX文字，不掃描註解、著色器及只用於相容查表的舊錯誤鍵。靜態掃描只針對明確口語和禁句，不能取代逐篇閱讀。

舊引擎會依選項文字推導心性、關路及餘韻。事件顯示文字可修改；既有推導使用固定的`mechanics_text`／`mechanicsText`，不得隨文案調整而改變。三百個事件選項的固定種子比對須通過，並確認機率、效果、旗標、RNG及選項編號一致。

新產生的文字採用修訂版；既有存檔年譜與玩家自行輸入的姓名不改寫。
